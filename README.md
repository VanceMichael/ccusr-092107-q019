# 普通食品营销表述审签服务

围绕普通食品营销素材的**版本化资料、逐条表述证据、审签与投放留痕、投诉时点还原**建立的领域服务。
处理的核心问题：投诉人员从某个渠道截到一张包装图时，合规团队必须能回答——

1. 消费者看到的是**哪一版正面文案**（不是当前版本，是截图当时的版本）；
2. **真实配料**是什么（包装钉住的配方版本与截图当时现行生产配方是否一致）；
3. **明星代言覆盖哪些商品、渠道、受众、期限**；
4. 每条成分/功效暗示**证据的适用范围**到哪（配方版本、检验批次、法律意见依据的法规版本）；
5. 只有一份抽检合格报告**不能**结束调查——质量合格不证明成分宣称，更不证明功效；
6. 商标被无效、法规换版时，**仍在投放的受影响素材**是哪些；
7. 完整还原发布时间、受众、当时依据与后续处置（下架、澄清、投诉反馈）。

所有编号、人员、主体均为虚构示例，不含真实个人信息。

## 模块

| 文件 | 职责 |
| --- | --- |
| `src/ledger.js` | 只增审计台账：事件按序追加、`prev_hash`/`hash` 哈希链串联，篡改可被 `verify()` 发现 |
| `src/registry.js` | 版本化实体投影：类别、配方、商标、包装、渠道页面、代言、检验资料、法律意见、法规；支持按时间点取生效版本（`versionAt`） |
| `src/claims.js` | 表述—证据适用范围评估：对每条成分暗示/功效暗示/风味/名称近似逐条核对，输出 `allowed/conditional/blocked`、支撑证据及其范围、不适用证据（如抽检报告对功效宣称） |
| `src/service.js` | 审签主服务：送审、多角色审批（乐观并发控制）、批准签发、投放校验、复用/回流/代言异常、下架澄清、商标法规变更影响扫描、投诉关联与时点还原、取证包导出与重建 |
| `src/scenario.js` | 完整虚构剧本，重放一条真实调查会遇到的时间线（见下） |
| `src/ids.js` | 实体引用 `kind/id@version`（如 `recipe/RC-TANG@v2`） |
| `src/context.js` | 基础领域事实的读取校验（沿用既有样例） |

## 关键领域规则（由代码强制）

- **抽检合格 ≠ 表述合法**：检验资料只证明所列批次的质量指标；对功效暗示一律列入 `not_applicable`，必须另有法律意见。
- **成分暗示必须对得上真实配方与含量**；含量不足为附条件，配方中不含则阻断。
- **法律意见只在其依据的法规版本有效期间成立**；法规换版后旧意见阻断批准，须按新规重出。
- **包装钉住的配方版本停用时评估直接阻断**，防止旧包装按旧配方继续宣称。
- **普通食品不得作功效/疾病暗示**；名称与药品近似须同屏满足规定标注。
- **批准只覆盖确定的包装版本**：投放版本与批准不一致即拦截（旧图回流嫌疑）；渠道、受众、期限、地域均在批准范围内核验。
- **代言授权按版本管理**：期限、渠道、受众、覆盖商品清单逐一比对，超范围产生异常事件。
- **澄清只能在已下架之后发出**，不允许"只澄清不下架"。
- **产品侧角色不能审批自己提交的素材**；批准须法务与合规双角色齐备，签发时点再做一次合规复核。

## 留痕场景（全部在剧本中出现并由测试锁定）

剧本 `src/scenario.js` 的时间线：

1. 登记类别/配方/商标/法规/法律意见/抽检报告/代言授权（均带适用范围）；
2. 包装 v1 含"提神抗疲劳"功效暗示，送审即被否，评估写入台账（含"抽检报告不适用"说明）；
3. 包装 v2 删改后重新送审，法务用旧修订号审批触发**并发冲突**（`review.blocked` 留痕），按新修订号重审后批准；
4. 天猫批准投放；素材**跨渠道复用**到拼多多另走批准，当时代言不含拼多多，记录代言超范围异常，随后代言授权升版覆盖；
5. 快手渠道 + 青少年受众的**超范围投放被拦截**（`placement.blocked`），不产生投放；
6. 配方变更（人参 0.3g→0.1g/100g）：旧批准撤销、在投放下架，包装出 v3 重审；新批次检验资料单独登记；
7. 渠道运营私自重上 v2 旧图，巡检通过 `placement.observed` 记录**未批准上架与旧图回流**事实，强制下架后发布写明"现行含量 0.1g"的澄清；
8. 商标被裁定无效：**影响扫描**列出仍在投放的素材和仍指向旧素材的渠道页面，下架并澄清；
9. 法规换版：在途审批被扫描标出，按新规重出法律意见、包装 v5 才获批；
10. 9 月收到投诉，截图时间为 6 月旧图回流当晚：按截图时间还原"看到的版本/包装配方 vs 现行真实配方/当时依据/无批准上架/后续处置链"，投诉关联与处置结论全部留痕。

## 运行

```bash
npm test                 # 22 个测试：台账、版本化、证据范围、并发、复用/回流、变更影响、投诉还原、重建
npm run build:fixtures   # 重放剧本，导出 fixtures/bundle.json 与投诉还原报告
```

导出产物：

- `fixtures/bundle.json`：只增台账取证包（事件 + 哈希链 + `verified`），可用 `ApprovalService.fromEvents` 重建出一致状态；
- `fixtures/complaint-reconstruction.json`：投诉时点还原摘要（看到的文案、真实配料、不适用证据、处置链、变更扫描、被拦截尝试）；
- `fixtures/roles.json`：产品侧（产品经理、品牌运营、研发配方师、渠道运营、代言方）与审核侧（法务、合规、质量、投诉处置、合规负责人）样例；
- `contracts/*.schema.json`：取证包与角色样例契约。

## 还原一份投诉需要的字段

`service.reconstruct({ placement_id, at })` 返回：投放元信息（发布时间、渠道、受众、地域、来源）、消费者看到的包装版本与逐字稿、包装钉住配方、`at` 时点现行真实配方及是否一致、代言引用、批准依据（含各法规在 `at` 是否仍有效）、当时表述复核结论、异常事件、后续处置链、台账尾哈希与完整性结论。
