# 食品营销表述审签

界定普通食品配料、商标、营销素材和审查证据的关系。

## 领域资料

`contracts/context.schema.json` 约定基础资料格式，`fixtures/context.json` 提供不含真实个人信息的示例。代码模块只负责读取和校验这些资料，后续业务服务可以沿用其中的领域标识与版本约定。

当前资料记录了以下业务事实：

- 争议产品属于普通食品且配料与同名药品不同
- 抽检合格与营销表述是否合法不是同一问题
- 代言扩大曝光后更需要区分商标与商品成分

## 本地校验

运行项目自带测试可确认示例资料能够读取，且领域标识、版本和事实列表完整。示例中的编号均为虚构值，不包含账号、凭据或真实主体信息。

## 审签服务

在领域资料之上提供普通食品营销审签能力，全部动作写入追加式留痕日志（`src/audit.js`）。

- `src/registry.js`：八类资料（商品类别、配方、商标状态、包装、渠道页面、代言范围、检验资料、法律意见）按版本登记，旧版本保留有效期，可按时间还原任一时刻的生效版本。
- `src/claims.js`：每条成分或功效暗示必须附证据，并校验证据适用范围（表述类型、商品、渠道、时间）；抽检合格报告只覆盖所检批次与项目，不能支撑功效暗示。
- `src/service.js`：送审与多角色审签（决定带“当时依据”快照，并发审批冲突、评审期间依据变化均留痕）；投放时识别旧图回流、跨渠道复用与证据越界；法规或商标状态变化时自动标出仍在投放的受影响素材；支持下架、澄清、投诉关联与事后还原。
- `src/seed.js` + `fixtures/seed.json`：虚构的产品与审核角色样例及基础资料时间线（普通食品胶原蛋白饮品，与同名药品配料不同）。

投诉调查视图按渠道与观察时间定位消费者实际看到的投放版本，给出该版包装正面文案、当时配方与当前配方、代言覆盖的商品与渠道范围、每条表述的证据适用范围，而不是只凭一份抽检合格报告结束调查。`reconstruct` 可还原任一投放的发布时间、受众、当时依据和后续处置（影响标记、下架、澄清、投诉）。

运行 `npm test` 执行全部单元与场景测试。
